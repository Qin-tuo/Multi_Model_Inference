# 当前 Goal：B2 主线整合与可复现交付

以当前 B2 为唯一运行主线，完成代码整合、旧版本清理和可复现交付，形成结构清晰、职责明确、便于阅读与性能分析的端侧多模型项目。完成后，由你接手性能优化。

本轮保留当前十个视觉模型及 TensorRT 后端，继续使用 D435i 原生深度；4B、ASR、TTS 和四服务架构保持现有方案。

1. 建立重构前的恢复点与清单

   梳理当前未提交改动，保留其他工作的修改。记录现有代码版本、模型与依赖哈希、有效配置、功能验证和 B2 性能基线。

   为文件和工件明确用途：当前运行必需、构建验证必需、实验、历史、可删除。清理以实际引用关系为依据。
2. 统一当前版本的启动与配置

   让 run.sh、Python 入口、服务管理器和配置加载器默认选择同一方案，保留显式配置覆盖能力。

   消除当前代码中由 B0/B1/B2 演进遗留的默认值冲突。运行模块按职责命名，模型版本通过清单管理，历史版本通过 Git 记录表达。
3. 解除新旧实现耦合

   提取帧处理、模型加载、工件校验、图像变换、计时和资源管理等公共能力。

   当前二维姿态不再从旧三维实现中借用公共函数，当前感知管线不再依赖旧方案的业务实现。B2 仍在使用的七个模型及其必要代码继续保留。
4. 整理核心模块职责
   - 应用入口负责组装资源和生命周期。
   - 采集模块负责 RGBD、音频及时间戳。
   - 感知模块负责目标选择、模型调用和结果关联。
   - 模型适配器负责各模型必要的预后处理。
   - 轮次控制负责请求状态、取消和工具执行边界。
   - 语音输出负责生成、播放或文件发布。
   - 诊断模块负责指标采集与展示。

   拆分 pipeline.py、TurnController 等职责过重的实现，保留明确的资源所有者和释放顺序。
5. 整合构建、验证与基准工具

   将公共逻辑迁入正式模块，消除 01_src 反向导入 scripts 的依赖。

   按构建、验证、基准、部署组织工具；命令入口负责参数和任务选择。合并可以参数化复用的流程，归档只服务于旧版本的一次性脚本。
6. 让旧版本退出当前主线

   移除旧版专用业务代码、配置和日常入口，不再同时维护多套运行方案。

   历史源码通过 Git 标签保留；当前重构所需的 B2 固定输入、引擎、基线和关键失败证据继续保存。历史实验和报告退出当前使用路径。

   用户提供的原始 ONNX、references/ 和第三方许可证单独保留，不随旧版本清理自动删除。
7. 制作并验证当前版本运行包

   整理当前运行真正需要的模型、辅助代码、环境和原生程序，生成匹配新代码版本的 B2 运行包及校验清单。

   在独立目录恢复，验证启动、模型加载、相机、文字／文件语音链路和服务停止，确认不依赖旧项目路径。新包恢复验证通过后，再清理被替代的旧运行包和无引用工件。
8. 完成回归、性能对照与交接

   核验十模型数据流、帧与目标归属、距离触发、挥手／张掌规则、整轮取消、持久化及资源释放。

   使用相同输入、模型和参数对照 B2 基线，记录功能差异与性能变化，调查未解释的退化。B2-EXIT-01 退出超时单独记录定位和处置状态，未解决时继续保持开放。

   更新启动说明、架构图、目录地图、模型清单、清理记录和复现命令，分阶段提交并推送远端。

完成判定：

- 默认入口一致，当前主线不依赖旧版专用实现。
- 公共模块与命令脚本的依赖方向清楚。
- 核心功能和有效回归检查通过。
- 当前运行包能够独立恢复。
- 清理内容有依据，基线和必要证据可追溯。
- 功能变化、性能退化及未关闭问题如实记录。
- 用户能从一个文档入口完成启动、理解数据流并复现基准。

本轮不开展模型更换、量化、剪枝、并发调优或新增功能，也不引入新的大型框架。文件数和行数作为统计信息，不作为删减目标。


执行状态以 `benchmarks/manifests/consolidation-progress.json` 为准。系统 Goal 已由用户设置为 active。
