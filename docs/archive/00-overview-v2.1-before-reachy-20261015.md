# 机器人端侧AI项目总计划

> 更新：2026-10-14。当前求职主线：端侧模型部署、嵌入式AI推理、机器人推理系统与性能优化。
> 本机负责项目二：Orin NX 16GB上的多模型部署与资源调度；项目一仍由RK侧独立维护。
> 当前仅修订计划，实施Goal保持暂停。具体目标、任务与验收以项目二v2.1为准。

## 1 项目定位

目标能力是：能把真实模型部署到受限设备，正确处理模型间数据、时序与资源，解释并改善端到端性能，在异常和重新部署后仍能保持可预期行为。

陪伴机器人提供真实混合负载。人体、人脸、手部感知持续运行，ASR、4B主模型和TTS按请求工作，交互控制及工具服务同时存在。项目二重点产出部署兼容、数据流、资源管理、profiling、可靠性和可复现实验的工程证据。

既有电机驱动、Linux外设、USB-CAN和中间件经验，可以直接连接到设备恢复、时序、线程与缓冲所有权等工作；模型转换、推理后端、精度回归和GPU分析构成需要补充的能力。

## 3 岗位能力与项目分工

公开岗位样本来自蔚来AI模型部署/性能优化、京东机器人推理部署、双深模型部署和西图部署优化。其技术交集用于设计本项目；用户具体学历、年限及目标HC资格不做假设。高级岗位的编译器/算子深度列为进阶，不把所有招聘关键词转成必做功能。

| 能力 | 项目二必须提供 | 项目一可补充 |
|---|---|---|
| 模型落地 | GGUF/ONNX/engine、预后处理、精度与兼容性 | RK后端工件、设备接口与模型落地 |
| 软件工程 | C++/Python/Linux、成熟框架适配、资源所有权 | 驱动/通信/执行反馈 |
| 多模型运行 | 持续感知与交互模型共存，数据流/取消/背压 | 语义到执行任务状态 |
| 系统分析 | CPU/GPU时间线、队列/拷贝/计算、内存/温控 | 平台专有NPU/总线瓶颈 |
| 交付 | 自检、故障、离线、重部署与可复现报告 | 真机动作及恢复证据 |

项目二不使用SO-101、机械臂、底盘或RK计算补偿。项目一的实体执行工作仍由RK计划维护，本轮不改动其实现。两项目独立运行；跨平台条目需要两端都有可复核实测结果。

## 4 项目二的两级交付

**A：软件基础版本。** 固定Qwen3.5-4B及已有成熟后端，补齐人脸/手部感知，贯通人体/脸/手→语音→语义→实体回应，落实挥手问候、静止举掌整轮取消。排查和修复迟到回调、重复工具、错误状态、服务恢复和资源泄漏。性能先作诊断，缺失音频硬件时只交付明确标记的A-software。

**B：指导式性能优化与作品集。** 由助手在整体功能贯通后先交付当前性能基线，用户再在指导下亲自使用工具定位问题、提出假设、完成修改和比较；助手不自动代替用户完成优化。 建立统一资源账本和冻结场景，完成B0/B1/B2及优化B3、部署精度对照、真实瓶颈与资源策略收益、8h/故障/离线/重部署验证。形成有真实代码和数据支持的简历与面试材料。

长期记忆的质量容量与产品扩展另阶段；已有Mem0/Qdrant及数据保留，当前会话、笔记和提醒仍是负载的一部分。身份验证删除，人脸只检测/定位。Edge-LLM仅用于后续独立后端对照。

## 5 技术基底和个人贡献

沿用Pipecat、ROS2/realsense-ros/yolo_ros、llama.cpp、ORT/TensorRT、OpenVoiceStream和APScheduler。新增人脸/手部优先复用OpenCV Zoo模型与参考代码，完成本机验证后才计入当前配置。

个人贡献集中于：部署适配和数值问题定位、C++数据路径/生命周期实现或补丁、跨模块状态正确性、资源策略、profiling与可复现对照。上游已有能力、配置、自己的实现及验证范围分别说明。

当前246项历史框架回归、4B的8轮文件/文字集成及42项针对性测试，都只证明各自覆盖范围；不能代替新感知链路、物理音频或最终整机验收。当前阶段的真实缺口以项目二和问题台账为准。

## 6 跨平台与资源安排

| 资源/工作 | 使用方式 |

| Orin NX16GB | 项目二唯一在线计算设备，CPU/GPU共享资源统一计量 |

| references/ | 原有资料保留，不因路线重设计删除 |

跨平台对照优先选择相同模型/输入和同一取消/过期行为契约。量化、精度、输入或模型不同只能比较产品配置，不能把差异直接归因于后端或平台。没有第二端证据时，简历只写实际完成的Orin工程。

## 7 求职作品集与完成判定

最终至少能展示：一个真实机器人交互场景；一个部署/精度根因案例；一个多模型资源竞争与优化案例；原生代码贡献；可复现部署与故障证据。

简历按部署、系统、优化三条组织，平台/模型/负载和收益均对应证据。项目名称建议“面向陪伴机器人的Jetson端侧多模型部署与资源调度”。不把使用某框架描述为开发该框架，不把编译CUDA后端描述为编写CUDA算子。

A按SF-01～06，B按DP-01～10判断。原JT-01～13和旧J0～J7保存在历史计划，不与新版口径混用。工作量和排期依据每个阶段的真实缺口更新，不用测试条数或已启动服务数计算整体完成率。
