# 工具开发语料

`tool-quality-v1.json` 固定100条合成中文请求，覆盖10个类别。每例先建立独立档案与已知SDK状态，再运行真实Pipecat/llama.cpp/BGE，核对操作、参数、实际记录与反馈。评测使用临时Mem0、APScheduler和SQLAlchemy数据库，不操作日常档案。

这是开发集，由实现者编写并用于调试；它不是独立盲测，也不包含物理语音或提醒播放验收。预期结果在首轮之前固定，不能为了提高分数降低要求。自然语言内容采用声明的实体/字段条件，不宣称完整语义等价性已被自动判定。

```bash
.venv/bin/python tools/tool_quality.py \
  --output benchmarks/results/tool-quality-development.json
```

可用 `--ids T006,T024` 或 `--limit 10` 运行子集；报告会注明实际覆盖范围。完整报告逐例保留请求、预期、调用参数、操作前后状态、回复和失败原因。模型实际生成的 `provider_arguments` 与应用依据可信输入补齐的 `arguments` 分别记录。

相对时间对照实际请求接受时间；“明天”等表达对照同一时区日期；显式日期用执行日后14天填充，避免测试数据过期。T026使用“今天23点”，应在当天23点之前评测；正式独立验收语料还需覆盖日期边界、时钟变化和更多用户表达。

63/100的原始失败基线、99/100的第一次修复报告与后续报告分别保留。判定要求开发集联合条件通过率至少95%，不出现否定/澄清/查询中的意外修改，重复回调不得产生额外修改或丢失既有回执。达到此开发门槛不表示JT-12已经完成；独立100例验证和20次真实提醒开始播报测量仍需单独证据。

## 容量语料

`memory-capacity-v1.json`固定1k/10k/50k各档的事实生成模板、100个查询编号、50次完整写入和时延门槛。大档可使用SDK批量准备初始数据，实际方法记入每份报告；计时操作使用完整应用适配器。编号近似记录用于观察稠密检索的弱点，不能把这里的召回率当作独立记忆语言质量验收。各档的编号集合不同，不据跨档命中率推断模型质量随容量变化。

## 外部中文记忆语料

`lcvmem-v1.json`锁定官方CLongEval/LCvMem小集358题、70组对话。按完整对话分为82题开发集、200题保留集和76题备用集，避免同一对话跨分区。当前仅运行20个开发问题，保留集未运行。数据和原始问答保留在AI_Stack；仓库仅记录标识、哈希和指标。词级F1不等于JT-10语义正确率，详见[评测方法与对照](../../deploy/evaluation/README.md)。
